# 05 · 性能优化

## 0. 铁律：先测后改

不接受"感觉慢"。优化前必须拿到数据：

| 工具 | 拿什么 | 用途 |
|---|---|---|
| Performance Analyzer（Desktop 视图） | 每个视觉的 DAX 查询 / 视觉显示 / 其他 耗时 | 定位是哪个视觉、哪段耗时 |
| DAX Studio | Server Timings 的 SE/FE 耗时、SE 查询数、回调行数、物化行数 | 定位是公式引擎还是存储引擎 |
| 模型指标（VertiPaq Analyzer / `model-size-report`） | 各表/列占用、基数 | 定位模型体积瓶颈 |

**判定经验**：
- FE 耗时占比高 → 逻辑问题（迭代、上下文转换、复杂度）。
- SE 查询数多（> 10） → 度量值或视觉设计问题。
- 物化行数巨大（百万/千万级回到 FE） → 需要降基数或预聚合。
- 单列占用模型 50% 以上 → 该列是优化首要目标。

阈值参考（需与用户确认后写入验收标准）：首屏 < 5s，单视觉 < 3s，SE 查询 < 1s，模型体积 < 目标内存配额。

## 1. 模型层（收益最大，优先做）

| 手段 | 检查点 | 预期收益 |
|---|---|---|
| 删列 | 未被任何度量值/视觉/关系引用的列 | 体积与刷新时间线性下降 |
| 降基数 | DateTime 拆日期 + 时间；GUID 移除；Double 改 Fixed Decimal；长文本截断或抽维度 | 高基数列往往是体积 80% 元凶 |
| 数据类型 | 能用 Int 不用 String；金额用 Fixed Decimal | 压缩率提升 |
| 关系 | 单向、整数键；避免多对多 | 查询计划简化 |
| 聚合表 | 大事实表按「日期 × 常用维度」预聚合，命中自动重定向 | 扫描行数降 1–2 个数量级 |
| 复合模型 | 明细 DirectQuery + 聚合 Import | 兼顾实时与性能 |
| 分区 | 增量刷新 | 刷新时间从小时级降到分钟级 |

> 用 `model-size-report` / `model-inspector` 技能生成体检结果，再据此动手。

## 2. DAX 层

### 2.1 输出格式（必须对比）

```markdown
### 优化：<度量值名>
**问题原代码**
```dax
...
```
**实测数据**：FE xx ms / SE xx ms / SE 查询数 x / 物化行数 x
**优化后代码**
```dax
...
```
**提升原理**：（具体到"减少一次对事实表的迭代 / 布尔筛选下推到 SE / 避免上下文转换"）
**预期效果**：（量化区间 + 需实测复验）
**风险**：口径是否变化、边界条件（空值/多对多）行为是否一致
```

### 2.2 常见瓶颈与改写

| 症状 | 原因 | 改写 |
|---|---|---|
| `SUMX(FILTER(Fact,...))` 慢 | FE 逐行迭代 | 布尔筛选放进 `CALCULATE`，或上游预计算列 |
| `FILTER(ALL(...))` 当筛选器 | 生成大中间表 | 直接条件表达式 / `TREATAS` |
| 多个 `IF`/`SWITCH` 分支各算一遍全表 | 重复扫描 | `VAR` 提公共结果；或改计算组 |
| `DISTINCTCOUNT` 高基数列 | SE 大扫描 | 预聚合表 / `APPROXIMATEDISTINCTCOUNT`（误差约 2%，需业务认可） |
| 度量值在不同粒度行为异常 | 未处理上下文 | 显式 `REMOVEFILTERS` / `KEEPFILTERS` |
| 计算列依赖其它计算列 | 刷新串行、内存膨胀 | 合并为一步或上游处理 |
| 时间智能在 DirectQuery 慢 | 逐次回源 | 用计算组 + 物化日期表，或改 Import 聚合 |

### 2.3 折叠与合并
- 多个相似度量值 → 计算组（时间口径）或字段参数（指标切换）。
- 度量值总数超过 100 时先做归并评估，避免维护失控。

## 3. 报表层

| 手段 | 说明 |
|---|---|
| 控制视觉数量 | 单页 ≤ 15 个；超出的拆页或用书签分页 |
| 关闭不必要交叉筛选 | 卡片图设为"无"；矩阵/图表之间评估是否需要联动 |
| 减少切片器 | 层级切片器替代多个独立切片器；用筛选窗格 |
| 默认筛选收敛 | 默认显示最近 N 天/当前月，避免首屏全量 |
| 明细表分页 | 表格开启"分页"或限制 Top N + 下钻 |
| 自定义视觉谨慎 | 部分第三方视觉未优化，渲染耗时高 |
| 图片/背景 | 避免使用大体积背景图与高分辨率 logo |

## 4. 优化流程

1. 收集基线（Performance Analyzer / DAX Studio 导出，保存为证据）
2. 按 模型 → DAX → 视觉 顺序逐项改
3. 每改一项复测一次，记录前后数据
4. 输出优化报告：基线 / 措施 / 复测 / 结论 / 遗留风险
5. 回归 UAT：确认数字未变（性能改动最容易悄悄改变口径）
