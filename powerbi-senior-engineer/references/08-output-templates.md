```markdown

### 方案 B
<说明 + 适用条件>
### 方案对比
| 维度 | A | B |
|---|---|---|
| 实现复杂度 | | |
| 性能 | | |
| 维护成本 | | |
| 风险 | | |
| 推荐 | ★ | |

## 3. 风险登记表
| 风险 | 类型 | 影响 | 概率 | 缓解措施 | 责任方 |
|---|---|---|---|---|---|

## 4. 验证方法

| # | 事项 | 阻塞? | 默认假设 | 需谁确认 |
|---|---|---|---|---|
```

复杂技术任务默认给 2–3 个方案并明确推荐项；简单任务可直接给唯一方案并注明"本场景无更优替代"。

## 2. 风险登记表规范

风险类型固定四类：
- **性能**：扫描行数、内存、刷新时间、并发
- **数据准确性**：口径歧义、对账基准、历史数据兼容
- **需求歧义**：术语多义、边界未定义、缺失验收标准
- **兼容性**：Power BI 版本、Desktop/服务差异、DirectQuery 函数支持、旧报表依赖

每条风险必须有**缓解措施**，没有缓解措施的风险等于没有识别。

## 3. 待确认项规范

- 必须区分**阻塞 / 非阻塞**；阻塞项要说明"不确认会导致什么后果"。
- 必须给**默认假设**，让用户可以只回复"按默认"继续推进。
- 涉及口径的待确认项，同步更新到《指标口径确认表》。

## 4. 术语与口径速查表（长期维护）

| 术语 | 业务含义 | 技术定义 | 首次出现项目 |
|---|---|---|---|
| 销售额 | 已出库含税金额 | `SUM(Fact_Sales[Amount_TaxInc])`，排除取消单 | xx 项目 |

每个项目维护一份，避免同一个词在不同报表含义不同。

## 5. 交付前自检清单（通用）

- [ ] 结论在第一句
- [ ] 代码块语法完整、字段名自洽、未臆造未确认对象
- [ ] 风险表齐全且每条有缓解措施
- [ ] 验证方法可执行、有通过标准
- [ ] 待确认项编号、标注阻塞性、给了默认假设
- [ ] 敏感字段已提示脱敏/聚合/OLS
- [ ] 未使用官方不推荐或已废弃写法
- [ ] 数字给出单位与口径（含税？T+1？币种？）
