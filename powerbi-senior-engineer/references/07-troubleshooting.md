# 07 · 问题处理与排障

## 1. 五步法（固定输出顺序）

```
1. 现象   → 复现条件、报错原文、影响范围、首次出现时间、最近变更
2. 定位   → 判定层级：数据源 / 模型 / DAX / 权限 / 报表渲染 / 服务
3. 排查   → 每层给出可执行的检查项与判断依据
4. 结论   → 根因（写清楚"为什么"，不是"可能是"）
5. 方案   → 临时止血 + 永久修复 + 规避措施 + 回归验证
```

**先止血后根治**：生产故障先恢复可用性（回滚版本/暂停刷新/切换数据源），再查根因。

## 2. 分层定位决策树

| 现象 | 先查层级 | 关键检查项 |
|---|---|---|
| 打开报表报错 / 视觉显示错误图标 | DAX / 模型 | 报错原文、最近改动的度量值、DAX Studio 单跑该度量值 |
| 数字与源系统不一致 | 口径 / 关系 / 筛选 | 见 §3 数据差异五维排查 |
| 刷新失败 | 数据源 / 网关 / 凭据 | 刷新历史错误详情、网关状态、凭据过期、源表结构变更、查询折叠失效 |
| 部分用户看不到数据 / 看到全部数据 | 权限 | RLS 角色、View as 验证、USERPRINCIPALNAME 返回值、关系方向 |
| 页面卡顿 | 报表 / DAX | Performance Analyzer → DAX Studio，见 `05-performance-tuning.md` |
| 某视觉空白但无报错 | 筛选 / 关系 | 筛选上下文是否有交集、外键是否有孤儿值 |
| 移动端显示错位 | 报表 | 移动布局画布是否单独排布 |

## 3. 数据差异排查（五个维度，按顺序过）

| # | 维度 | 检查方法 | 典型根因 |
|---|---|---|---|
| 1 | **口径差异** | 拉出《指标口径确认表》逐条比对：含税/不含税、是否含退货、统计时点（下单/出库/开票）、币种 | 业务说的"销售额"是开票额，模型算出库额 |
| 2 | **数据链路延迟** | 对比源系统数据时间、ETL 完成时间、模型刷新时间 | 源晚到 + 已刷新 → 数字偏小 |
| 3 | **模型关系错误** | 检查基数、方向、是否非活动、外键是否有孤儿值 | 关系未激活导致时间筛选失效 |
| 4 | **筛选上下文** | 在 DAX Studio 复现：加/去切片器看变化；检查页面级筛选、同步切片器、钻取继承 | 页面隐藏筛选器未清除 |
| 5 | **数据质量** | 空值、重复主键、负值、单位换算 | 源表重复行导致翻倍 |

### 对账方法
```dax
-- 1) 行数与源对比
_QA_行数 = COUNTROWS ( Fact_Sales )

-- 2) 按月对比，定位差异发生在哪个期间
_QA_月度差异 =
VAR Bi  = [Sales_销售额]
VAR Src = <源系统基准值>   -- 手填基准表或另一个查询
RETURN Bi - Src

-- 3) 检查孤儿外键（被静默丢弃的行）
_QA_孤儿行数 =
CALCULATE ( COUNTROWS ( Fact_Sales ), ISBLANK ( RELATED ( Dim_Customer[CustomerKey] ) ) )
```
推荐做法：建一张"对账基线表"（源系统导出的月度值），在报表内做一个隐藏的 QA 页，随时可查差异。

## 4. 常见报错速查

| 报错 / 现象 | 根因 | 处理 |
|---|---|---|
| 检测到循环依赖关系 | 计算列里 `CALCULATE` 引发上下文转换；两个计算列互相引用 | 改度量值；或用 `ALLEXCEPT` 显式限定；或上游处理 |
| 列包含重复值 / 关系无法创建 | 一端表主键不唯一（含空值或重复） | 去重、补 Unknown 成员、检查粒度 |
| 函数 'XXX' 在此上下文中不支持 | 在 DirectQuery 下用了不支持的函数，或在计算列里用了迭代 | 改 Import / 上游计算 / 换等价写法 |
| 内存不足（Out of memory） | 高基数列、大表全量刷新、中间表过大 | 删列降基数、增量刷新、升级容量/改聚合表 |
| 凭据无效 / 数据源未找到 | 密码过期、网关离线、服务器迁移 | 更新凭据、检查网关、改用参数化连接 |
| 查询超时（DirectQuery） | 源端慢或 DAX 生成 SQL 复杂 | 建索引/物化视图、改 Import 聚合、简化 DAX |
| 视觉对象超出资源限制 | 单个查询返回行/列过多 | 限制 Top N、分页、减少列 |
| RLS 看起来不生效 | 关系双向、角色未发布、用户不在映射表 | 改单向、重新发布、补映射并 View as 验证 |

## 5. 生产故障处理流程

| 优先级 | 判定 | 响应 | 目标恢复 | 动作 |
|---|---|---|---|---|
| P0 | 全量不可用 / 数据错误影响决策 / 越权泄露 | 立即响应，拉群 | 2 小时 | 止血（回滚/暂停/隐藏）→ 定位 → 修复 → 公告 |
| P1 | 核心模块不可用或明显变慢 | 1 小时内 | 当日 | 降级方案 → 修复 → 回归 |
| P2 | 局部异常，有规避方式 | 当日 | 3 个工作日 | 排期修复 |
| P3 | 体验问题 | 下期 | — | 记录待办 |

必备动作：影响范围说明、用户公告模板、恢复后数据重对账、24 小时内出复盘。

## 6. 复盘报告模板

```markdown
# 故障复盘：<一句话标题>
## 1. 问题描述
- 时间线（发现 → 响应 → 止血 → 恢复 → 关闭，精确到分钟）
- 影响范围：报表 / 用户数 / 数据期间 / 业务决策影响
## 2. 处理过程
- 每一步做了什么、依据是什么、效果如何
## 3. 根本原因（5 Why 或鱼骨，写到可落地的层）
- 直接原因：
- 根本原因：
## 4. 为什么没早发现
- 监控 / 测试 / 评审的哪个环节缺失
## 5. 改进项
| # | 改进措施 | 类型（技术/流程/监控） | 责任人 | 截止 | 验收方式 |
## 6. 经验沉淀
- 需更新的规范 / 需补的用例 / 需加的监控
```
