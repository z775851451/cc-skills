# 01 · 沟通协同模块

## 1. 需求拆解

业务方给模糊描述时，先问清并填齐**5 项核心要素**，缺项直接标 `<待确认>`。

| 要素 | 要问清什么 | 常见坑 |
|---|---|---|
| 指标口径 | 分子分母、是否去重、是否含税、币种/汇率、退货是否冲减 | "销售额"含不含税、含不含运费 |
| 统计粒度 | 行级粒度（订单/订单行/日/月）、展示粒度 | 度量值在明细行上的行为未定义 |
| 数据来源 | 系统、表、字段、更新频率、历史回溯起点 | 源系统本身有重复行 |
| 交付时效 | T+1 还是准实时、截止日期 | 未约定刷新 SLA |
| 验收标准 | 与哪个系统对账、允许误差、谁签字 | 无对账基准，UAT 无法收敛 |

输出模板：

```markdown
### 需求：<需求一句话>
- 业务背景：
- 5 要素表：（上表）
- 歧义点：
  | # | 歧义描述 | 影响 | 建议默认口径 | 待谁确认 |
- 非功能要求：性能目标 / 权限 / 移动端 / 导出
- 交付物与排期：
```

**歧义分级**：阻塞（不确认无法开工）/ 非阻塞（可先按默认口径开发）。

## 2. 指标口径确认表

《指标口径确认表》必须包含以下列，一行为一个指标：

| 业务术语 | 技术定义 | 计算逻辑 | 统计粒度 | 筛选条件 | 异常值/空值处理 | 对账基准 | 数据截止 | 责任人 | 状态 |
|---|---|---|---|---|---|---|---|---|---|
| 销售额 | 已出库订单金额（含税） | `SUM(Fact_Sales[Amount_TaxInc])` | 订单行 | 排除测试账号、排除已取消 | 负数按红冲保留；空值计 0，不参与去重计数 | ERP 月结报表 | T+1 02:00 | 张三/李四 | 待确认 |

填写规则：
- **技术定义**用一句话说清"什么范围、什么时点、什么口径"，避免同义词（营收/销售额/开票额必须区分）。
- **异常值处理**必须明确：负值、空值、极值时是保留、剔除还是截断。
- **对账基准**必须落到具体系统+报表名+期间，禁止写"与财务核对"。
- **状态**：待确认 / 已确认 / 有争议。有争议的走升级流程，不进开发。

## 3. 需求变更评估

四维影响矩阵：

| 维度 | 评估内容 | 结论 |
|---|---|---|
| 开发工作量 | 新增/改造对象数、DAX 复杂度、测试范围 | 人日 |
| 性能风险 | 是否引入高基数、是否新增迭代、是否破坏聚合表命中 | 高/中/低 |
| 数据链路 | 是否需上游改造、是否需重刷历史、是否影响其他报表 | 受影响清单 |
| 历史兼容性 | 已发布指标口径是否被改变、历史报表数字是否变动 | 是否需并行期 |

输出结构：

```markdown
### 变更：<变更内容>
**结论**：接受 / 有条件接受 / 建议延到下期
**影响评估**：（四维矩阵）
**排期建议**：原定 X 日 → 变更后 Y 日，关键路径：
**风险提示**：（风险登记表）
**前置条件**：需业务方在 <日期> 前确认 <事项>，否则影响 <后果>
```

判定经验：
- 改动**已发布指标口径** → 一律"有条件接受"，必须设并行期与变更公告。
- 改动**模型关系/主键粒度** → 视为高风险，需全量回归。
- 仅新增视觉对象/新页面 → 低风险，可当期吸收。

## 4. 沟通话术模板

### 4.1 正式邮件

```markdown
主题：【Power BI】<事项> - <结论关键词> - 需<行动> <截止日期>

<收件人> 好，

核心结论：<一句话，含决策与影响>

关键信息：
1. <事实/现状>
2. <影响范围>
3. <建议方案>

需您支持：
| 行动项 | 责任人 | 截止 |
|---|---|---|

如有异议请于 <日期> 前反馈，逾期将按上述方案执行。
```

### 4.2 会议纪要

```markdown
# <主题> 会议纪要
- 时间 / 参会 / 记录人
## 结论（核心信息前置）
1.
## 讨论要点
- 议题 → 分歧点 → 结论
## 行动项
| # | 行动 | 责任人 | 截止 | 验收方式 |
## 待决议（未达成共识，需升级）
```

### 4.3 风险告知函

```markdown
# 风险告知：<风险一句话>
- **风险描述**：
- **影响范围**：受影响的报表 / 用户 / 期间
- **触发条件**：
- **当前应对**：已采取的措施与效果
- **需要决策**：选项 A（代价/收益） / 选项 B（代价/收益） / 建议选项
- **不决策的后果**：
- **反馈时限**：
```

## 5. 输出检查
- [ ] 5 要素齐全，缺项已标待确认
- [ ] 口径表每行都有对账基准与责任人
- [ ] 变更评估给了明确结论（不是"可能有影响"）
- [ ] 所有沟通件都带行动项 + 责任人 + 截止日期
